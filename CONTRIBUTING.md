# Contributing to DB-Crusher

First off, thank you for considering contributing to DB-Crusher! It's people like you that make DB-Crusher a great learning resource for backend engineering.

## How to Contribute

### 1. Reporting Bugs
If you find a bug in the code or a mistake in the course documentation, please open an issue on GitHub. Include as much detail as possible:
*   Your operating system.
*   Your Go version.
*   Steps to reproduce the bug.

### 2. Suggesting Enhancements
Want to add a new chapter? Want to implement a new caching strategy (like Memcached) or a new database (like MySQL) for comparison? 
*   Open an issue first to discuss your idea.
*   Once approved, you can start writing the code!

### 3. Pull Requests
The core of open source is the Pull Request (PR). Here is how you submit one:

1.  **Fork the repository** to your own GitHub account.
2.  **Clone the project** to your machine.
3.  **Create a new branch** for your feature or bug fix: `git checkout -b feature/your-feature-name`.
4.  **Make your changes** and commit them with descriptive commit messages.
5.  **Push your branch** to your fork on GitHub: `git push origin feature/your-feature-name`.
6.  **Open a Pull Request** from your fork to the `master` branch of this repository.

### Code Style
*   Ensure all Go code is properly formatted by running `go fmt ./...` before committing.
*   Make sure your markdown documentation is clear, concise, and uses proper grammar.

Please note that this project is released with a [Contributor Code of Conduct](CODE_OF_CONDUCT.md). By participating in this project you agree to abide by its terms.
